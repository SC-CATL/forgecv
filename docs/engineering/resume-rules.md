# 简历规则：健康度与 JD 覆盖

> 状态：M4 已实现。代码在 `features/resume/checks.py` 与 `features/resume/jd.py`。
> 所有规则本地执行，不联网、不调用模型。

## 1. 渲染数据

`ResumeRenderer` 把版本与七个切片组装成 `ResumeDocument`（`features/resume/document.py`），
预览与 M5 的 Word 导出共用这份数据：

- 条目来源：`resume_items` 勾选的学历 / 经历 / 项目 / 技能 / 证书；
- **未勾选任何条目时，预览包含全部内容**，并在文档末尾标注；
- 项目自动带标签与指标，技能按分类分组，日期统一为 `yyyy.MM – yyyy.MM` 或「至今」。

## 2. 健康度检查

| 级别 | 规则 |
|---|---|
| 必须处理 | 个人信息缺姓名 |
| 建议处理 | 没有教育经历；没有项目经历 |
| 建议处理 | 工作经历或项目的亮点没有任何数字（未量化） |
| 建议处理 | 存在没有证据链的技能 |
| 可选优化 | 未填写目标岗位 |
| 可选优化 | 部分项目没有技术标签 / 量化指标 |
| 可选优化 | 当前版本未勾选条目（预览为全部内容） |

检查只给建议，不阻断保存；M5 导出前会把「必须处理」作为阻断项。

## 3. JD 覆盖

- 词表是 `VOCAB`（约 60 个常见语言、框架、数据库、工程实践词）；
- 在 JD 文本中做大小写不敏感的子串匹配，得到「岗位要求词」；
- 已知能力词来自：技能名称、标签名称、项目方向；
- `覆盖 = 已匹配要求词 / 要求词总数`；
- 缺口列出词表中命中 JD、但你的技能/标签里没有的词；
- JD 中没有词表内的词时返回 0 并提示，不猜测。

## 4. 已知限制

| 限制 | 说明 |
|---|---|
| 词表有限 | 新框架需要手动加入 `VOCAB` 或先录成标签/技能 |
| 同义词不合并 | `JS` 与 `JavaScript` 视为两个词 |
| 中文分词未引入 | 只做子串匹配，避免引入分词依赖 |
| 健康度不判语义 | 只做可解释的结构与量化检查 |
