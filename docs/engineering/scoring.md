# 能力雷达口径

> 状态：M3 已实现，代码在 `features/dashboard/service.py`。
> 雷达是**自评 + 档案完整度**的混合指标，不是职业能力排名，导出时必须标注「自评」。

## 1. 八个维度

| 维度 | 数据来源 | 计算 |
|---|---|---|
| 编码 | `skills.level` | 全部技能 `level/4×100` 的平均值；无技能为 0 |
| 架构 | `projects.architecture` | 填写了架构说明的项目占比 |
| 测试 | `projects.ci_status`、`practice` 标签 | 有 CI 状态，或带 `CI/CD`、`测试`、`单元测试`、`集成测试`、`TDD` 标签的项目占比 |
| 性能 | 项目指标、`performance` 标签 | 指标键含 `QPS`、`P99`、`延迟`、`耗时`、`吞吐`、`内存`，或带 `性能优化`、`压测`、`可观测性` 标签的项目占比 |
| 运维 | `toolchain` 标签、运维技能 | 带工具链标签或 `Docker`/`Kubernetes`/`CI/CD`/`Linux`/`运维` 标签的项目占比；没有项目时按「运维」分类技能等级折算 |
| 协作 | `experiences.highlights` | 有量化成果条目的经历占比 |
| 文档 | 项目架构 / 复盘 | 填写架构或复盘任一字段的项目占比 |
| 交付 | `projects.status`、`repo_url` | 状态为 `online` 或填写了仓库地址的项目占比 |

所有分值取 0–100 的整数，空数据集返回 0。占比类维度衡量「档案完成度」，不是代码质量。

## 2. 标签分布

- 按 `tags.dimension` 聚合项目的 `project_tags` 使用次数；
- 每个维度最多展示 6 个标签；
- 维度中文名来自 `TagService.dimensions()`，不在视图层硬编码。

## 3. 改进提示

概览页同时给出可执行提示：

| 条件 | 提示 |
|---|---|
| 技能没有任何 `skill_evidence` | 「N 项技能还没有证据」 |
| 项目没有任何标签 | 「N 个项目还没有技术标签」 |
| 项目没有任何 `project_metrics` | 「N 个项目没有量化指标」 |

## 4. 设计约束

1. 不联网、不调用模型、不做排名；同一份数据每次计算结果一致。
2. 权重固定为「每维最多 100 分」，暂不做可调权重（避免引入无依据的调参）。
3. 新增维度必须先改本文件与测试，再改代码。
4. 导出 Word 时若包含雷达，必须写明「自评」与口径来源。
