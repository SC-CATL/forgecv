# ADR 0003：项目标签固定四维度

- 状态：接受
- 日期：2026-11-21
- 决策者：项目发起人

## 背景

「技术宅标签」如果做成自由文本，很快会退化为几十个同义标签，无法筛选与统计。
需要一套稳定、可统计、又不至于过度设计的标签体系。

## 决策

- 标签只允许四个维度：
  - `language`：编程语言，如 Python、C++、Rust
  - `domain`：业务 / 技术领域，如 嵌入式、推荐系统、编译器
  - `practice`：工程实践，如 单元测试、CI/CD、性能优化、可观测性
  - `toolchain`：工具与平台，如 Docker、PostgreSQL、GitHub Actions
- `tags.name` 全局唯一，避免同义重复；维度决定它在筛选器与统计图里的分组。
- 项目与标签多对多（`project_tags`）。
- 不允许标签嵌套、父子层级或自定义维度；确需扩展时先改本 ADR。
- 颜色只用于界面展示，不参与语义。

## 后果

正面：
- 筛选与统计稳定，雷达图、标签分布、JD 匹配都有确定口径。
- 命名冲突在录入时即可发现（唯一约束）。
- 用户心智简单：看到标签就知道它属于哪一类。

代价：
- 少数跨维度标签需要拆成两个。
- 自由表达受限，需要在 `description` 里补充说明。

## 替代方案

| 方案 | 不采用原因 |
|---|---|
| 自由文本标签 | 同义词泛滥，无法统计 |
| 无限层级树 | 录入成本高，个人工具用不上 |
| 每个项目自定义字段 | 无法横向比较与聚合 |

## 后续动作

- M2 建标签库与打标界面，内置一套常用标签种子数据。
- M3 标签分布与能力雷达按维度聚合。
- 若确需第五维度，先新增 ADR 并给出迁移方案。
