# ADR 0001：本地优先，SQLite + WAL

- 状态：接受
- 日期：2026-11-21
- 决策者：项目发起人

## 背景

ForgeCV 是个人简历工具，数据包含真实姓名、联系方式、任职经历与项目细节。
需要在离线环境可用，且安装后零配置启动。候选方案：本地 SQLite、本地 JSON 文件、
远程数据库（需账号体系）。

## 决策

- 数据存本机 SQLite，默认路径 `%LOCALAPPDATA%/ForgeCV/app.db`。
- 开启 WAL，写操作串行化，避免 UI 线程阻塞与 `database is locked`。
- 通过 SQLAlchemy 2.x + Alembic 管理模型与迁移，保留切换 MySQL 的能力但不默认启用。
- 不引入账号、同步、遥测；导出物与备份由用户自行管理。
- 测试环境使用内存 SQLite（`ENVIRONMENT=test`）。

## 后果

正面：
- 零服务端成本，隐私边界清晰，离线可用。
- 单文件备份 / 迁移，排障简单。
- ORM 与迁移让后续加表可控。

代价：
- 多设备需要手动复制数据库。
- 并发能力有限（个人工具场景可接受）。
- 数据库损坏只能靠备份恢复，因此必须提供自动备份与快照。

## 替代方案

| 方案 | 不采用原因 |
|---|---|
| JSON 单文件 | 无事务、无索引，关系与迁移难以维护 |
| 远程数据库 | 需要账号、网络与运维，违背本地优先 |
| 嵌入式文档库 | 生态与工具链弱于 SQLAlchemy + Alembic |

## 后续动作

- M1 实现统一备份入口（复制前先 checkpoint WAL）。
- M5 快照与导出都只读渲染数据，不直接复制数据库文件。
