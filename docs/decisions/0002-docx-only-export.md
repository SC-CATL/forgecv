# ADR 0002：首版只做 Word 导出

- 状态：接受
- 日期：2026-11-21
- 决策者：项目发起人

## 背景

简历需要交付给招聘方，常见格式有 PDF、Word、HTML、Markdown。首版资源有限，
需要选一个主格式，同时不把导出能力写死在某个格式上。

## 决策

- 首版唯一导出格式：`.docx`，使用 `python-docx` 在代码中构建版式。
- 导出层只消费 `resume` 切片提供的渲染数据（纯数据结构），不直接读表。
- PDF / HTML / Markdown 作为后续适配器，接口相同；不在首版实现。
- 版式规范写在 `docs/engineering/export-spec.md`，实现必须遵守。

## 后果

正面：
- Word 是国内招聘场景最通用的可编辑格式。
- 纯代码构建 docx，无外部模板文件，版式可测试、可版本管理。
- 渲染数据与格式解耦，后续加 PDF 成本低。

代价：
- docx 的中文字体需要显式设置 `w:eastAsia`，否则可能字体回退。
- 复杂排版（分栏、页眉页脚）能力弱于 HTML/CSS。
- 无法一次性满足「必须交 PDF」的岗位。

## 替代方案

| 方案 | 不采用原因 |
|---|---|
| 先做 PDF | Qt 打印对中文字体与分页控制复杂，首版调试成本高 |
| HTML + 浏览器打印 | 依赖外部浏览器，交付链路长 |
| 外部 docx 模板 | 模板与代码双份维护，字段缺失时容易静默错位 |

## 后续动作

- M5 先实现 docx，再补导出前检查与文件名规则。
- 加 PDF / HTML 时新增适配器，不改 `resume` 数据契约。
